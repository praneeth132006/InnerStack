# Contributing to InnerStack

First off, thanks for taking the time to contribute! 🎉

InnerStack is an open-source project, and we love receiving contributions from our community — whether it's fixing bugs, improving documentation, or proposing new features.

## 💡 How to Contribute

### Reporting Bugs
This section guides you through submitting a bug report.
- **Check existing issues**: Verify that your issue hasn't already been reported.
- **Open a new issue**: Explain the behavior you would expect and the actual behavior.

### Suggesting Enhancements
- **Open a new issue**: Describe your idea clearly.
- **Explain the value**: Why would this feature be useful to most users?

### Pull Requests
1. **Fork the repo** and create your branch from `main`.
2. **Install dependencies**: `npm install`
3. **Make your changes**: specific, focused changes are best.
4. **Test your changes**: Ensure the app builds and runs correctly.
5. **Format your code**: We use standard linting rules.
6. **Push to your fork** and open a Pull Request.

## 🧑‍💻 Development Workflow

1. **Branch Naming**:
   - `feat/feature-name`
   - `fix/bug-fix`
   - `docs/documentation`

2. **Commit Messages**:
   - Use imperative mood: "Add feature" not "Added feature"
   - Be descriptive.

## 🎨 Design System

We use `shadcn/ui` and `Tailwind CSS`. Please adhere to the existing design patterns.
- Use CSS variables for colors (e.g., `bg-primary`, `text-muted-foreground`).
- Ensure responsiveness (mobile-first).

## 🏢 Project Structure

- `/src/components`: Reusable UI components.
- `/src/lib`: Utilities and helpers.
- `/src/hooks`: Custom React hooks.
- `/src/pages` (to be added): Route components.

## ❓ Questions?

Feel free to open an issue or start a discussion if you have any questions!
